# Release summary

Turn the supplied list of changes into a short release summary.

## Procedure

1. Group changes into: behavior changes, fixes, and internal work.
2. Lead with behavior changes; internal work comes last.
3. Keep each item to one line, in plain language, no ticket jargon.
4. Never invent a change that is not in the supplied list.
